## [1.2.1] - 2026-09-24

Patch release. Two security/data-loss fixes when opening `.zsmt` bundles,
a Linux start-up crash fix, PDF export fixed in built copies, and a new
GitLab release pipeline that builds a Windows installer, portable zip,
Linux AppImage and Flatpak. The app now reports version 1.2.1.

### Security

- **Opening a `.zsmt` bundle can no longer write files outside its work
  folder.** A crafted bundle with a floor id such as `../x` used to write
  `x.drawio` outside `<bundle>_work/`. Every file name taken from the
  bundle is now flattened (both `/` and `\` count as separators, `.` and
  `..` are rejected). Regression tests added.

### Fixed

- **A floor named `project.wiremap.json` no longer loses its plan on
  extract.** Its `.drawio` was written and then overwritten by the project
  file; that name is now reserved, so such a floor becomes
  `project.wiremap_2.json`. Regression test added.
- **PDF export works in the built exe.** reportlab was only a dev extra,
  so release builds shipped without it and "Export PDF" asked users to
  pip install it. It is now a runtime dependency, and the build fails if
  it cannot be bundled.
- **The app no longer crashes on start-up on Linux.** It asked Tk for the
  Windows/macOS-only `zoomed` window state; it now falls back to X11's
  `-zoomed` attribute, or the default size. Windows is unchanged.
- Frozen Linux builds bundle `PIL._tkinter_finder`; before this, the
  frozen Linux app crashed as soon as the floor plan was drawn.
- Inside an AppImage, projects and floor plans next to the `.AppImage`
  file are found automatically, as they are next to the Windows exe.

### Added

- App icon (`packaging/icons/`, generated by `packaging/make_icon.py`),
  embedded in the exe and used by the installer, AppImage and Flatpak.
- Windows installer script (`installer/windows.iss`, Inno Setup):
  Start-menu shortcut, optional desktop shortcut, uninstaller, installs
  per-user without a UAC prompt by default.
- Linux AppImage build script (`packaging/linux/build_appimage.sh`),
  using a pinned, SHA-256-checked appimagetool 1.9.1.
- Flatpak manifest and metadata (`packaging/flatpak/`), freedesktop 25.08
  runtime, X11 + home-folder access only.
- `packaging/check_bundle.py`: fails a build whose binary is missing
  sv-ttk, reportlab or Pillow's Tk bridge (handles Windows and Linux
  archive paths).
- Tests for the Linux maximise fallback, the AppImage project lookup and
  the bundle checker.

### Changed

- Linux builds need glibc 2.35+ (Ubuntu 22.04+, Debian 12+, Fedora 36+);
  RHEL/Rocky/Alma 9 are not supported.
- README: new "Downloads / Building" section (release files, how to cut a
  release, local builds, Inno Setup licence note); reportlab listed as a
  regular dependency.
- Version bumped to 1.2.1 in `cwt/__init__.py`, `pyproject.toml`, the
  Flatpak metainfo and the installer's default version.

### Dependencies

- Added runtime dependency `reportlab>=4.0` (`requirements.txt`,
  `pyproject.toml`).
- New `packaging/requirements-build.txt` pins `pyinstaller==6.22.3` and
  `pyinstaller-hooks-contrib==2026.7` for all frozen builds.

### CI

- **New GitLab CI pipeline** (`.gitlab-ci.yml`), run on `v*` tags and
  manual/API triggers: tests, then the Windows exe, portable zip and
  installer (on the Windows runner), the Linux AppImage (Ubuntu 22.04
  base) and the Flatpak, published to the GitLab Release and Package
  Registry.
- Version gate: a tagged or `RELEASE_VERSION` build fails early unless
  `cwt.__version__` and `pyproject.toml` both match the release version;
  a manual `RELEASE_VERSION` run must be started on the matching tag.
- The release job checks that the tag points at the commit being
  published and cannot be cancelled mid-publish.
- Windows runner tools (`ci/tools-windows.ps1`): SHA-256-pinned Python
  3.12.10 + Tcl/Tk and Inno Setup 6.7.3; a corrupt cached download is
  moved aside (never deleted) and fetched once more.
- The existing GitHub Actions workflow is unchanged.

## [1.2.0] - 2026-07-02

Correctness release: a full-codebase audit (9 parallel review passes over
the app + cwt package) surfaced ~35 real defects; everything confirmed
was fixed. Highlights below.

### Fixed — measurement & coverage correctness

- **FOV cones were drawn at the wrong size on calibrated plans.** The
  renderer passed `1/scale` where `cone_polygon` expects inches-per-pixel,
  so every DORI cone was off by scale² — on this repo's own Floor 1
  (0.6 in/px) cones drew at ~⅓ of their true radius, understating camera
  coverage on screen AND in exported PDFs. Both call sites fixed.
- **DORI Observation threshold corrected to 62.5 px/m** (was 62) per
  IEC EN 62676-4.
- **Camera tilt now affects coverage**: `compute_fov` caps the
  ground-projected DORI distances at the geometric far edge of the
  vertical FOV (`h / tan(tilt − vfov/2)`), as the docs always promised.
  Untilted cameras are unchanged.
- Waypoint edit commands recompute wire lengths with the effective
  (alignment-aware) scale + riser verticals, matching `_recalc_all_wires`.
- Grid snap used the X pixel scale on the Y axis — devices snapped off
  the painted grid when the page/image aspect ratios differ.

### Fixed — data loss & persistence

- **Failed project-file writes no longer mark the app clean**: a locked
  `.wiremap.json` (OneDrive/AV) used to clear the dirty flag and delete
  the crash autosave — closing then lost every wire/scale/annotation
  change silently.
- **Undo/redo stacks are cleared on floor switch.** Undoing a Floor 1
  command while on Floor 2 used to replay it against Floor 2's state
  (`ClearWiresCmd.undo` could replace Floor 2's wires with Floor 1's).
- **Deleted devices stay deleted**: the save-time sweep now removes any
  parsed device cell, not just ids starting with "s" — devices that came
  from the source .drawio no longer resurrect on reload.
- Device resizes (transform gizmo) persist — width/height are written
  back to the .drawio.
- Autosave recovery refuses to overlay a snapshot from a different
  floor/drawio (used to graft Floor 2's devices into Floor 1's file);
  the autosave path now survives multi-floor project adoption; explicitly
  discarding changes at close also discards the stale autosave.
- Opening a floor's .drawio directly reconciles `active_floor`, so the
  right floor's wires/annotations load onto the right plan.
- Floor switch aborts when the pre-switch silent save didn't complete.
- Opening a `.zsmt` salvages newer loose work files into a revision
  instead of silently rolling the project back; revert waits for the
  in-flight safety snapshot and writes restored files atomically.
- Insert-waypoint undo no longer deletes a pre-existing endpoint when
  the insert had no-opped on an exact-duplicate point.
- Corrupt v2 project files with zero usable floors fall back to a fresh
  single-floor project instead of crashing at startup.

### Fixed — selection & interaction

- **`_selected_wire` mapped listbox rows through the wrong table** in
  grouped sorts (the default view): Simplify, Z-zoom, minimap highlight,
  and waypoint dragging all acted on the WRONG wire (or none).
- Canvas context menu / double-click on a wire filtered out of the Wires
  list no longer acts on the previously-selected wire.
- Hidden wires (hidden device type / unwired filter) no longer intercept
  canvas clicks and hover; lasso selection skips hidden devices and works
  on rotation-aligned floors (containment now tested in canvas space).
- Del with a stale Wires-tab selection no longer silently deletes an
  off-screen wire while the Devices tab is active.
- "Center on Selected" preserves multi-selections.
- Reassign-wire dialog no longer crashes on the "(no matches)" row.
- Typing spaces in a search field no longer triggers full-canvas redraws.
- Room-label text cells without a fillColor are no longer auto-classified
  as cameras (they polluted camera counts, bulk-FOV actions, and the BOM).
- "Assign model" works for non-camera devices (WAPs/readers) as the menu
  always advertised, and no longer wipes hand-aimed FOV azimuths.
- Camera-model prices like "$1,299" are validated instead of silently
  saving as $0 and understating the BOM.

### Fixed — rotated floor alignments (whole-pipeline)

- Background placement under a rotated alignment: the expand-rotate
  recentering used the un-rotated half-size, so the plan slid under the
  device/wire overlays as you panned. Corrected placement algebra
  (verified numerically to <1 px across rotations/scales/zooms).
- The drag-align dialog previewed a center-pivot rotation but stored an
  origin-pivot transform — Apply landed the floor thousands of pixels
  from the previewed match at 90°. The preview now renders exactly the
  stored transform (WYSIWYG), and spinning the rotation control keeps
  the layer visually anchored.
- Ghost floor overlay honors the ghost's alignment rotation; its
  aspect-distorting size cap replaced with a proportional one.
- Grid overlay draws alignment-transformed segments over the 4-corner
  visible range (it previously vanished at 90–270° and painted a false
  grid at other angles); viewport-size cap no longer shrinks the
  background on >4000 px canvases.
- Anchor alignment composes through an already-aligned reference floor,
  so chained alignments keep scale (wire lengths / BOM were off by the
  reference's scale factor).

### Fixed — exports

- **Multi-floor PDF summary was built from whichever floor the user was
  viewing**, not the exported floors. It now aggregates the exported
  floors' snapshots, labels them correctly, skips floors that fail to
  switch (previously: the prior floor's map under the failed floor's
  caption), surfaces render errors as dialogs, and cleans up temp PNGs.
- Map PNG snapshot export always failed (`ValueError: unknown file
  extension .tmp`) — format now derived from the real target path.
- `wires.csv` resolves cable types with the project default, matching
  `bom.csv` in the same bundle; BOM "by device type" panel applies the
  same stale-cable validation as the rollup.
- CSVs are written UTF-8 **with BOM** so Excel renders em-dashes and
  currency correctly.
- PDF export dialog warns when scale isn't calibrated, like the other
  export paths.
- `.zsmt` revision extraction uniquifies colliding floor basenames
  (previously one floor's plan silently overwrote the other's) and
  writes atomically.

### Changed

- Version 1.2.0 (pyproject + `cwt.__version__` now agree; they had
  drifted since 1.1.0).
- Test suite: 398 → 417 (+19 covering the DORI threshold, tilt capping,
  CSV project-default threading, stale-cable inventory, bundle basename
  collisions, and zero-floor project fallback).

## [1.1.0] - 2026-06-12

### Changed

- **Auto-routing removed.** A* pathfinding produced too many paths through
  walls and around them awkwardly on real construction blueprints; the user
  preferred manual wire drawing with snap-to-orthogonal (Shift) and
  snap-to-points. The `cwt.routing` module is retained for tests and a
  potential future rework but is no longer wired into the UI.
- Drawing wires manually is now the only path (Wire mode + click points,
  or right-click a device → "Draw wire from here…").
- Map annotations: drop styled text labels on the floor plan with full
  undo coverage and per-floor persistence.
- Atomic file writes everywhere: .drawio, project file (v2 .wiremap.json),
  autosave, settings, recent files, log rotation, PDF export, all CSV
  exports, and PNG map snapshots — torn writes are no longer possible.
- Wires follow their associated device when the device is moved (smart-
  follow with tolerance for manually-placed endpoints).
- Cable type per-wire override via right-click menu.
- Universal undo coverage: every catalog/state mutation goes through a
  Command, including FOV (single + bulk + clear + rotate-coalescing),
  cable-type catalog edits, annotations, and wire-cable overrides.
- Arrow-key device nudge (Shift = 10× step) with coalescing so held
  keys don't flood the undo stack.
- Ctrl+D duplicate, Ctrl+U jump-to-next-unwired-camera, F11 fullscreen.
- DPI-aware on Windows (SetProcessDpiAwareness) so the canvas renders
  crisply at >100% display scaling.
- Test suite grew from 37 → 114 pytests covering BOM rollup, FOV/DORI
  math, alignment math, project-file round-trips, every Command class's
  do/undo cycle, malformed-input tolerance, and the pre-export scale
  guard.

### Roadmap

- **v1.1.0** — Auto-detected wall opening (re-attempt routing once the
  wall geometry is reliable); per-room reports; per-camera FOV defaults
  saved with the symbol type.
- **v1.2.0** — Cloud sync; per-installer field app for checkoff & photos.

## [1.0.0] - 2026-05-07

### Added

- **`cwt/` package** for pure-logic modules:
  - `cwt.models` — TypedDicts for Device / WireRoute / SymbolType / Floor / Riser
  - `cwt.bom` — cable catalog defaults, BOM rollup, CSV writer
  - `cwt.fov` — IEC 62676-4 DORI math (Detection / Observation / Recognition / Identification)
  - `cwt.lenses` — sensor + lens + resolution + install-preset databases
  - `cwt.routing` — soft-A* on a downsampled obstacle grid (8-direction, diagonal-penalized, wall-penalty for soft mode)
  - `cwt.multifloor` — project file v2 schema, anchor-point alignment math, v1→v2 migration
  - `cwt.export` — multi-page PDF report (reportlab) + CSV bundle (BOM, devices, wires)
- **`tests/`** — 37 pytest tests covering BOM rollup, FOV/DORI math, A*
  pathfinding, alignment math, project file round-trips
- **Cable types + BOM**:
  - Default catalog (Cat6, Cat5e, RG59, OM4, Speaker, Alarm) with cost/ft
  - 4th side-panel tab with sortable BOM table, waste multiplier, tax,
    currency, grand-total breakdown
  - Cable Types editor dialog (add/edit/delete cables)
  - Per-route `cable_type` override; falls back to symbol-type cable;
    falls back to category default
- **Camera FOV / DORI overlays**:
  - Per-camera lens / sensor / resolution / mount-height / tilt / azimuth
  - Live DORI distances (D/O/R/I) computed from IEC 62676-4 thresholds
  - Semi-transparent cones rendered on the map (View menu toggle)
  - "Show DORI rings" sub-toggle (off → only outermost detection cone)
  - Quick presets: Lobby, Hallway, Reception desk, Parking, Loading dock,
    Long corridor, Server room
  - Right-click camera → Edit FOV…
- **A\* auto-routing** *(removed in unreleased — see top of changelog)*:
  - Wall detection from background-image threshold (lazy-built obstacle grid)
  - Soft-walls A* (walls penalized 8× rather than impassable — matches
    real cable behavior through ceiling/conduit penetrations)
  - 8-direction movement with diagonal penalty so paths prefer orthogonal
  - Auto-route mode (segmented control + `A` shortcut + right-click
    "Auto-route from here…")
  - Path simplification collapses colinear runs to ~5–20 waypoints
- **Multi-floor + anchor-point alignment**:
  - Project file format upgraded to v2 (auto-migrates v1 single-floor)
  - Floors menu: Add Floor, switch active floor, alignment dialog,
    floor manager
  - Anchor-point alignment: click 2 corresponding points on each floor,
    similarity transform (translation + rotation + uniform scale)
    computed and stored
  - Manual nudge dialog for fine-tuning alignment
  - Risers (cross-floor cables) included in BOM rollup
- **Export**:
  - File → Export → BOM (CSV) — single CSV
  - File → Export → All CSVs — bundle of 3 (BOM, devices, wires)
  - File → Export → Project PDF Report — multi-page with cover, BOM
    table, riser list, per-device listing
- **Right-click context menu** on canvas:
  - For cameras: Edit FOV, toggle FOV cone, auto-route from, delete
  - For empty canvas: fit, toggle device IDs, toggle FOV
- **`A` keyboard shortcut** for auto-route mode

### Changed

- Project file format is now v2 by default (single-floor still works
  identically; v1 files auto-upgrade on first save)
- Wire routes can carry an optional `cable_type` field (preserved across
  save/load)
- Symbol types can declare a default `cable_type` (used by all instances)

## [0.2.0] - 2026-05-07

### Added

- **Sun Valley dark theme** via optional `sv-ttk` dependency (graceful fallback
  if missing).
- **`Mode` enum** replaces the four mutually-exclusive booleans
  (`move_mode`, `wire_mode`, `calibration_mode`, `placing_device`) — single
  source of truth for the active mode.
- **Segmented mode bar** in the toolbar (Move / Wire / Calibrate radios) with
  cursor changes, status-bar feedback, and `M` / `W` / `C` keyboard shortcuts.
- **Icon toolbar** with grouped sections: file ops, undo/redo, scale + zoom,
  mode segment, units, scale state, total wire readout. Tooltips on every
  button.
- **3-tab side panel**: Devices / Wires / Symbols, each with a per-tab search
  field (`Ctrl+F` focuses the active one).
- **Universal undo/redo command stack** (`Ctrl+Z` / `Ctrl+Y`) covering device
  moves, add/delete device, add/delete wire, clear-all-wires, edit symbol,
  delete symbol, and calibration. History capped at 100.
- **Real error handling**: file I/O wrapped in try/except with user-friendly
  dialogs; errors written to `~/.camera_wire_tool.log` for diagnostics.
- **Keyboard shortcuts**: `M`/`W`/`C` modes, `Ctrl+Z`/`Y`, `Delete`, `Esc`,
  `Home` (fit), `+`/`-` (zoom), `[`/`]` (cycle devices), Space-hold (temporary
  pan), `Ctrl+F` (search), `Ctrl+O`/`S`/`Shift+S`. Help → Keyboard Shortcuts.
- **Constants dataclass** (`C`): every former magic number named — debounce,
  viewport cap, hit-test margin, zoom factor/limits, legend row height, font
  clamps, history limit, etc.
- **Breadcrumb status bar** at window bottom showing mode + selected device +
  cursor coordinates with live real-world distance from origin (when scale
  set).
- **Dirty-state tracking**: window title shows `*` when unsaved; close prompts
  to save.
- **Recent Files** menu (last 6 files; persisted to
  `~/.camera_wire_tool_recent.json`).
- **Wire reassignment** dialog: change a wire's device association without
  redrawing it.
- **Toggle device IDs** on the map (View menu).
- **About** + **Keyboard Shortcuts** help dialogs.

### Changed

- **Repo organization**: project data moved to `data/` (with original PDF in
  `data/source/`); the simpler `measure_tool.py` moved to `old/` since
  `camera_wire_tool.py` supersedes it. Each new folder has a README explaining
  contents.
- `main()` now discovers `.drawio` files in `data/` first, then the script
  directory.
- `parse_drawio` raises a typed `RuntimeError` with context on bad XML rather
  than crashing the interpreter; corrupt project files no longer fail
  silently.
- Calibration dialog gets a Cancel button and `Esc` binding.
- Symbol-editor dialog has `Apply` + `Cancel` + Enter/Esc bindings.
