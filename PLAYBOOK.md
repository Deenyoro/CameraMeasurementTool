## Project Purpose

Estimate the total cable/wire required for a security camera network installation in the **a commercial building** building (Sheet A111B — First Floor Dimension Plan).

The workflow:
1. An architect provided a PDF floor plan
2. Someone placed security device icons on it in draw.io, creating a `.drawio` file
3. This tool loads that `.drawio`, lets you move cameras, draw wire routes along the actual paths wire would follow, and calculates total wire needed per device and overall

## The .drawio File Format (CRITICAL)

The `.drawio` file is XML. Understanding its structure is essential for parsing and saving.

### Top-level structure
```xml
<mxfile host="app.diagrams.net" type="device">
  <diagram id="floor1m" name="Floor 1 Security (Measurements)">
    <mxGraphModel dx="2000" dy="1400" grid="1" gridSize="10"
                  pageWidth="3024" pageHeight="2160" ...>
      <root>
        <mxCell id="0"/>                          <!-- root cell -->
        <mxCell id="1" parent="0"/>               <!-- default layer -->
        <mxCell id="bg" ... />                    <!-- background image -->
        <mxCell id="s10" ... parent="1"/>         <!-- device -->
        ...
        <mxCell id="legbox" ... parent="1"/>      <!-- legend container -->
        <mxCell id="legi0" ... parent="legbox"/>  <!-- legend icon -->
        <mxCell id="legt0" ... parent="legbox"/>  <!-- legend text -->
        ...
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

### Key dimensions
- **Page**: `pageWidth="3024" pageHeight="2160"` (drawio coordinate units)
- **Background image**: embedded as base64 PNG, actual pixel size is 4620 x 3300

### Background image cell
```xml
<mxCell id="bg" value="" 
        style="shape=image;image=data:image/png,iVBORw0KGgo..."
        vertex="1" parent="1">
  <mxGeometry x="0" y="0" width="3024" height="2160" as="geometry"/>
</mxCell>
```
- The PNG data is base64-encoded inside the `style` attribute after `data:image/png,`
- To extract: split on `"data:image/png,"`, take second part, split on `";"` to strip trailing style params, base64-decode

### Device cells (86 total in the original file)
```xml
<mxCell id="s10" value="MD" 
        style="ellipse;html=1;fillColor=#FFFF00;strokeColor=#0000FF;strokeWidth=2;fontSize=8;fontStyle=1;fontColor=#000000" 
        vertex="1" parent="1">
  <mxGeometry x="441.8" y="272.4" width="22" height="22" as="geometry"/>
</mxCell>
```
- `id`: unique identifier (e.g., `s10` through `s95`)
- `value`: the shortcode displayed inside the icon (e.g., `MD`, `360`, `PTZ`, `BC`, `CR`)
- `style`: semicolon-separated key=value pairs defining shape, colors, font
- `parent="1"`: means it's on the default layer (NOT inside the legend)
- `mxGeometry`: position (x, y) and size (width, height) in drawio page coordinates

### Legend box
```xml
<mxCell id="legbox" value="Symbols" 
        style="rounded=0;html=1;fillColor=#FFFFFF;strokeColor=#0000FF;strokeWidth=2;fontSize=14;fontStyle=1;verticalAlign=top;align=center" 
        vertex="1" parent="1">
  <mxGeometry x="50" y="1400" width="340" height="740" as="geometry"/>
</mxCell>
```
- Located at bottom-left of the page
- Children have `parent="legbox"` and their coordinates are RELATIVE to the box

### Legend icon children
```xml
<mxCell id="legi0" value="CR" 
        style="rounded=0;html=1;fillColor=#00E080;..." 
        vertex="1" parent="legbox">
  <mxGeometry x="20" y="38" width="22" height="22" as="geometry"/>
</mxCell>
```
- `id` pattern: `legi0`, `legi1`, ... `legi17` (18 icon cells)
- Position is RELATIVE to `legbox` — actual page position = legbox.x + child.x

### Legend text children
```xml
<mxCell id="legt0" value="Card Reader Door" 
        style="text;html=1;align=left;verticalAlign=middle;fontSize=11;fontStyle=0" 
        vertex="1" parent="legbox">
  <mxGeometry x="55" y="36" width="275" height="26" as="geometry"/>
</mxCell>
```
- `id` pattern: `legt0`, `legt1`, ... `legt17` (18 text cells)
- Matched to icons by sorting both lists by y-position

### How we detect shape from style string
```python
def detect_shape(style):
    if "ellipse" in style:       return "ellipse"
    elif "hexagon" in style:     return "hexagon"
    elif "halfRect" in style:    return "halfrect"
    elif "step" in style:        return "step"
    elif "rounded=1" in style:   return "roundrect"
    else:                        return "rect"
```

### How we detect color from style string
```python
def detect_color(style):
    m = re.search(r'fillColor=(#[0-9A-Fa-f]{6})', style)
    return m.group(1) if m else "#FFFF00"
```

### Style templates for writing back to .drawio
```python
SHAPE_STYLES = {
    "ellipse":   "ellipse;html=1;fillColor={color};strokeColor=#0000FF;strokeWidth=2;fontSize={fs};fontStyle=1;fontColor=#000000",
    "rect":      "rounded=0;html=1;fillColor={color};strokeColor=#0000FF;strokeWidth=1.5;fontSize={fs};fontStyle=1;fontColor=#000000",
    "roundrect": "rounded=1;html=1;fillColor={color};strokeColor=#0000FF;strokeWidth=1.5;fontSize={fs};fontStyle=1;fontColor=#000000",
    "hexagon":   "shape=hexagon;html=1;fillColor={color};strokeColor=#0000FF;strokeWidth=1.5;fontSize={fs};fontStyle=1;fontColor=#000000",
    "halfrect":  "shape=mxgraph.bootstrap.halfRect;html=1;direction=south;fillColor={color};strokeColor=#0000FF;strokeWidth=1.5;fontSize={fs};fontStyle=1;fontColor=#000000",
    "step":      "shape=step;html=1;fillColor={color};strokeColor=#0000FF;strokeWidth=1.5;fontSize={fs};fontStyle=1;fontColor=#000000",
}
```
- `{color}` and `{fs}` are format placeholders
- `fs` (font size): 7 if shortcode is 3+ chars, 8 otherwise

## The .wiremap.json File Format

Companion file saved alongside the `.drawio`. Stores tool-specific data that doesn't fit draw.io's model.

```json
{
  "drawio_file": "Floor1_Security_Measurements.drawio",
  "scale_factor": 0.1234,
  "unit": "ft-in",
  "next_device_id": 96,
  "wire_routes": [
    {
      "points": [[100.5, 200.3], [300.1, 200.3], [300.1, 450.0]],
      "device_id": "s10"
    },
    {
      "points": [[500.0, 600.0], [700.0, 600.0]],
      "device_id": null
    }
  ],
  "summary_by_device": {
    "s10": {"runs": 2, "total_inches": 487.5},
    "unassigned": {"runs": 1, "total_inches": 312.0}
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `drawio_file` | string | Basename of the associated .drawio file |
| `scale_factor` | float or null | Inches per image pixel (set by calibration) |
| `unit` | string | `"ft-in"`, `"inches"`, or `"feet-dec"` |
| `next_device_id` | int | Counter for generating new device IDs |
| `wire_routes` | array | Each route has `points` (image pixel coords) and `device_id` (string or null) |
| `summary_by_device` | object | Quick-reference totals per device (regenerated on save) |

**Why two files?**
- `.drawio` stays draw.io-compatible (you can re-open it in draw.io and see all devices/legend)
- Wire routes are multi-point paths with device associations — draw.io has no equivalent concept
- The JSON is structured and queryable (e.g., grep for total wire per camera type)

## Coordinate System (CRITICAL)

There are **4 coordinate spaces**. Getting these wrong breaks everything.

### 1. Drawio page coordinates
- Range: 0..3024 (x), 0..2160 (y)
- Used by: `.drawio` XML geometry attributes
- This is where device positions are stored

### 2. Image pixel coordinates  
- Range: 0..4620 (x), 0..3300 (y)
- Used by: the embedded background PNG
- Wire route points are stored in this space (in `.wiremap.json`)

### 3. Canvas screen coordinates
- Range: depends on window size + zoom + pan offset
- Used by: Tkinter canvas drawing commands

### 4. Scale factors
```python
dx_scale = img_w / page_w  # 4620 / 3024 = 1.528 pixels per drawio unit
dy_scale = img_h / page_h  # 3300 / 2160 = 1.528 pixels per drawio unit
```

### Conversion functions
```python
def _drawio_to_img(dx, dy):    return dx * dx_scale, dy * dy_scale
def _img_to_drawio(ix, iy):    return ix / dx_scale, iy / dy_scale
def _img_to_canvas(ix, iy):    return ix * zoom + offset_x, iy * zoom + offset_y
def _canvas_to_img(cx, cy):    return (cx - offset_x) / zoom, (cy - offset_y) / zoom
```

### Legend child coordinates
Legend children (`parent="legbox"`) have positions RELATIVE to the legend box:
```python
actual_drawio_x = legend_box["x"] + child["x"]
actual_drawio_y = legend_box["y"] + child["y"]
```

## Rendering Pipeline

### Viewport cropping (performance-critical)
The background image is 4620x3300 pixels. Resizing the entire image on every frame is too slow for Tkinter. Instead:

1. Calculate which rectangle of the source image is currently visible on screen
2. Crop ONLY that rectangle from the full-res PIL image
3. Resize the crop to screen dimensions
4. Display as a PhotoImage

This gives full pixel detail at every zoom level while staying performant.

```python
def _get_viewport_image(self):
    # 1. What image region is visible?
    img_left, img_top = self._canvas_to_img(0, 0)
    img_right, img_bot = self._canvas_to_img(canvas_width, canvas_height)
    
    # 2. Clamp to image bounds
    src_x0 = max(0, floor(img_left))
    src_y0 = max(0, floor(img_top))
    src_x1 = min(img_w, ceil(img_right))
    src_y1 = min(img_h, ceil(img_bot))
    
    # 3. Crop and resize
    cropped = bg_image.crop((src_x0, src_y0, src_x1, src_y1))
    dst_w = int((src_x1 - src_x0) * zoom)
    dst_h = int((src_y1 - src_y0) * zoom)
    resized = cropped.resize((dst_w, dst_h), Image.LANCZOS)
    
    # 4. Position on canvas
    place_x, place_y = self._img_to_canvas(src_x0, src_y0)
    return ImageTk.PhotoImage(resized), place_x, place_y
```

### Draw order (in `_redraw`)
1. Background image (viewport crop)
2. Wire routes (so they appear under devices)
3. In-progress wire (dashed preview)
4. Device icons (on top of wires)
5. Legend box (on top of everything)
6. Calibration points (yellow dots)

### Debounced redraw
During zoom/pan, redraws are debounced at 16ms (~60fps) to prevent lag:
```python
def _schedule_redraw(self):
    if not self._redraw_pending:
        self._redraw_pending = True
        self.root.after(16, self._do_deferred_redraw)
```
A final crisp render happens on mouse release.

## Symbol Type System

Symbol types are the **templates** that define how a class of device looks. Each placed device references a type by its shortcode.

### Data structure
```python
self.symbol_types = {
    "MD": {
        "label": "Fixed Minidome Camera",   # shown in legend
        "shape": "ellipse",                  # one of SHAPE_OPTIONS
        "color": "#FFFF00",                  # hex fill color
        "is_camera": True                    # affects camera counts
    },
    ...
}
```

### How types are built (parse_drawio)
1. Parse legend icon cells (`legi*`) — extract shortcode, shape, color
2. Parse legend text cells (`legt*`) — extract label
3. Match icons to texts by sorting both by y-position
4. Camera detection: shortcode in `{"MD","360","PTZ","BC","180","HS","MI"}` OR `fillColor == "#FFFF00"`
5. Also scan placed devices — any device whose `value` isn't in a known type creates a new type auto-discovered from its style

### Renaming a shortcode
When the user renames e.g. `"MD"` to `"CAM"`:
1. Delete old key from `symbol_types`
2. Add new key with same info
3. Loop ALL devices: `if d["type"] == old_code: d["type"] = new_code`
4. Refresh symbol list, device list, redraw (legend auto-regenerates)
5. On save: the `.drawio` XML gets updated `value` attributes + regenerated legend

### Available shapes (6)
| Shape name | Drawio style | Canvas drawing |
|-----------|-------------|----------------|
| `ellipse` | `ellipse;...` | `create_oval` |
| `rect` | `rounded=0;...` | `create_rectangle` |
| `roundrect` | `rounded=1;...` | `create_rectangle` |
| `hexagon` | `shape=hexagon;...` | `create_polygon` (6 vertices) |
| `halfrect` | `shape=mxgraph.bootstrap.halfRect;...` | `create_arc` (180 degrees) |
| `step` | `shape=step;...` | `create_polygon` (5 vertices, arrow-like) |

## Device-Wire Association System

### How it works
1. User selects a device (click on map or in device list) — it highlights red
2. User switches to Wire Mode — status bar shows `"Wire Mode for s10 (MD - Fixed Minidome Camera)"`
3. User clicks to place wire route points along the path wire would follow
4. User right-clicks to finish — the wire route is saved with `device_id: "s10"`
5. User can select a different device and draw its wire — each wire is tagged independently

### What gets displayed
- **Device list** shows per-device wire totals: `s10  MD    [2w: 45'-6"]` (2 wire runs, 45 feet 6 inches total)
- **Wire list** shows device association: `s10    | 3 seg | 22'-4"` 
- **Map** draws wires in the associated device's color, with device ID in the label
- **Status bar** on click shows: `"Selected s10 (MD) — 2 wire run(s), total: 45'-6""`

### Unassigned wires
If no device is selected when entering Wire Mode, wires are tagged `device_id: null` and show as `"---"` in the wire list, drawn in default cyan.

## Legend Auto-Generation

The legend is NOT stored as parsed data — it's regenerated every frame from `self.symbol_types`.

### On-screen rendering (`_draw_legend`)
1. White rectangle at legend_box position
2. Title "Symbols" centered at top
3. For each type (sorted alphabetically by shortcode):
   - Icon at x=20, y=38 + i*38 (relative to box, in drawio units)
   - Label text at x=55, same y — includes instance count: `"Fixed Minidome Camera  (40)"`

### On save (in `_save_drawio`)
1. Remove ALL existing legend children (`parent="legbox"`) and the legbox itself from XML
2. Create new `legbox` mxCell with auto-sized height: `(num_types * 38 + 50)` drawio units
3. For each type (sorted alphabetically):
   - Create `legi{i}` icon cell with appropriate style template
   - Create `legt{i}` text cell with the label
   - Both have `parent="legbox"` and relative coordinates

## Save System

### What "Save All" does (in order)

**Step 1: Update .drawio XML**
1. Re-parse the original .drawio file from disk
2. Find `<root>` element
3. For each existing device cell in XML:
   - Update `value` attribute (in case shortcode was renamed)
   - Update `style` attribute (in case shape/color changed)
   - Update `mxGeometry` x/y (in case device was dragged)
4. Remove all old legend cells (legbox + children)
5. Add new device cells for any devices created in our tool (IDs not in original XML)
6. Remove device cells for any devices deleted in our tool
7. Generate new legend cells from `symbol_types`
8. Write XML to disk

**Step 2: Save .wiremap.json**
1. Serialize wire routes (points as `[[x,y],...]`, device_id as string or null)
2. Include scale_factor, unit preference, next_device_id
3. Compute summary_by_device for quick reference
4. Write JSON to disk

### Device ID generation
New devices get IDs like `s100`, `s101`, etc. The counter starts at 100 or `max(existing_ids) + 1`, whichever is higher.

## Tool 1: measure_tool.py — Generic Measurement

Simpler standalone tool that works with `schematic.png` directly (no .drawio parsing).

- Click two points to draw measurement lines
- Calibrate scale against a known dimension
- Side panel shows all lines + running total

## Known Issues & Future Work

1. **Wire routes are in image pixel coordinates** — if you change the background image resolution, existing wire routes will be misaligned. The .wiremap.json would need a migration.
2. **No undo for device moves** — dragging is immediate. You'd need to re-open without saving.
3. **Hit testing is bounding-box** — overlapping devices might be hard to select. Cameras are prioritized over non-cameras.
4. **Large zoom + large image** — the viewport crop caps at 4000px output dimension. At extreme zoom this slightly reduces sharpness.
5. **Legend position is fixed** — it's at drawio coords (50, 1400) and can't be moved in the tool.
6. **No wire re-assignment** — once a wire is tagged to a device, you can't change the association without deleting and redrawing it.

## Length Formatting

The `_format_length` function converts raw inches to display strings:

| Unit mode | Example output | Logic |
|-----------|---------------|-------|
| `ft-in` | `12'-6 1/2"` | `feet = inches // 12`, remainder to nearest 1/16" fraction |
| `inches` | `150.50"` | 2 decimal places |
| `feet-dec` | `12.54 ft` | 2 decimal places |

Fraction reduction: `sixteenths / 16` reduced by GCD (e.g., `8/16` -> `1/2`, `4/16` -> `1/4`).
